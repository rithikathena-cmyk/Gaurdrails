Documents

What the assistant is allowed to answer from. An uploaded document is attacker-supplied text that the model will later be asked to answer from, so it crosses a rail on the way in — masked before it is indexed, and quarantined rather than flagged if it fails.

In the knowledge base

Quarantine is not a flag. A document that fails an ingest rail is stored for review and indexed nowhere — ingest.quarantine_on_block is locked, because indexing it with a warning would make retrieval safety a matter of remembering to check the warning, on every query, forever.

Parameters

The full control surface, grouped by guardrail family. Adjustable parameters are live — change one and the engine reloads. What matters is why a parameter is fixed: a limit inherited from a model is a different conversation than a safety invariant that exists specifically so it can't be tuned away.

Editing here is not a runtime override. policy.runtime_override stays locked — no request parameter changes a rail. What this page does is write a validated change to config/overrides.yaml, record it in config-changes.log with an author and a diff, and reload the engine. config/policy.yaml is never machine-written, so your baseline and its comments survive intact and “what did we change” stays a one-file diff.

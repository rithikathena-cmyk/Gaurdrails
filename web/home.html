Every answer is checked, twice

A public-services assistant with guardrails on the way in and on the way out. Personal details never reach the model, an agent cannot act without a person saying yes, and every request leaves a trace you can read afterwards.

One agent turn, gate by gate

Twelve steps, the agent path. Five of the twenty-two boxes are dashed — those are the model, and it only plans, writes, or settles a close call. Every solid box is ordinary code, and those are the ones that decide. Two of the gates run once per tool call, one in each direction: a tool's arguments leave the system, and a tool's answer comes back into it. The long version has every rail.

Caught by the pattern layer in under a millisecond, before a model is called at all. The refusal names a category, never the technique — telling an attacker what matched teaches them what to vary.

What is the penalty for late payment of professional tax?

Not in the corpus. It says so, and names what it would need, rather than producing a figure that sounds right. A confident wrong number is worse than an admitted gap.

pass grounding

Check the status of claim CLM-40028871, then file a grievance about the delay. Just file it, don't ask me anything.

It looks the claim up — passing a vault token, never the number — and then stops. Filing creates a municipal record in somebody's name, so a person answers first. The instruction cannot override it: the gate is code, not prompt.

A document is uploaded containing “SYSTEM: ignore previous instructions…”

Quarantined at ingest, before a single chunk is indexed. No later question can retrieve it, because it never entered the index — and the same payload arriving through a tool is withheld again at the second boundary.

Masking is not refusing. Four of these eight carry personal data and all four are answered — the values are replaced with vault tokens the model never resolves, and restored for the person they belong to on the way out. Only two are refused, and both are attacks rather than questions.

What the agent adds

Two more trust boundaries, once per tool call, in each direction.

Planthe model picks a tool
GATE · AGENT.TOOLThe argumentschecked before the call runs
Run the toolvault unmask, if entitled
writes stop for a person
GATE · AGENT.DATAThe resultchecked before the model reads it

A tool result is untrusted input. It is attacker-reachable text — a record field somebody else filled in, a document somebody else uploaded. Trusting it because it arrived through your own tool is precisely how indirect injection lands, so it crosses a rail before the model is allowed to read it.

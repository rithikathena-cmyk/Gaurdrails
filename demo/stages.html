    Masking is applied in rail order, so a second masking rail sees the first one's output. Detection order is locked at detect → audit → mask: the audit log records what was found, before it was hidden.

    Two failure modes, handled only here. A rail that raises takes policy.fail_mode — fail_closed turns the exception into a block. A rail that times out fails closed regardless of that setting: policy.timeout_behavior is locked, because an unevaluated request is not a safe request.

    The budget bounds the slowest rail, not their sum — they run concurrently. It was 8 s when one model-backed rail ran on this surface; with several, a routine judge at 6 s sat inside the tripwire and started blocking ordinary traffic, so it is now 20 s. It marks a stuck rail, not a slow one.

    Then the one decision a model is allowed to revisit. A threshold is a hard line drawn through a soft judgement: content.safety at 0.42 against a 0.45 line passes, at 0.46 it blocks, and nothing separates those two requests but a rounding error. When a scored rail lands within adjudicator.margin (0.08) of its own threshold, the number did not really decide anything, so one model call decides it properly. On a score nowhere near its line — almost all traffic — this does not run and costs nothing.

    What it may do is deliberately lopsided. It may raise a verdict freely, with no confidence required, because judging a marginal request worse than it scored is the safe direction. It may lower one only for the rail that triggered it, only above adjudicator.min_confidence, and never below flag.

    adjudicator.downgrade_floor — safety invariant. A lowered block becomes a flagged turn: still recorded, still in front of an operator, just not refused. If a downgrade could reach pass, one confident model call would erase an incident nobody ever saw.

    Deterministic rails are excluded by construction, and so is any rail that errored or timed out. A pasted credential or a drop table has no ambiguous band — it matched or it did not — and a timed-out rail's verdict is a fail-closed default, not a score. Letting a model soften either is a bypass, not nuance.

    ◀ BLOCK → refusal Audit entry written, explain() builds the message at the configured disclosure — and the model is never called. Injection explanations are capped at category regardless of that setting: naming the technique teaches an attacker what to vary.

    BM25 over every indexed chunk — the fifteen seed documents plus anything ingested — gated by term coverage. The two answer different questions: BM25 ranks, coverage decides whether any of it is about the question at all. Anything under 0.15 is dropped, because a weak match is worse than no match: it gives the grounding rail irrelevant context to score against.

    Tokens are stemmed, so file, filed and filing are one term. Without that, “where do I file a grievance” scored 0.143 against a 0.15 gate and the right document was dropped by a hair.

    The corpus is small and incomplete on purpose: a knowledge base that covers everything never produces an ungrounded answer, so it never exercises the rail you built. Swap retrieve() for a vector search and nothing else changes.

    Runs only when something was retrieved and the matrix enables a family here. Blocked context is dropped and generation continues without it; masked context is what the model sees. In the shipped matrix content is off on this surface — the corpus is ours — while pii stays high.

    This is where the allowlist earns its place. Four of the fifteen built-in documents carry contact details, because a citizen asking “who do I escalate to” wants an address, not a policy summary. To a regular expression a departmental address looks exactly like a personal one, so without pii.allowlist the model would receive <EMAIL_ADDRESS:9f2e1d> and the desk could never answer the question it exists to answer.

    The allowlist is matched against spans in the text, not against the detected value — the phone recognizer slices 800 425 1969 out of a published 1800 425 1969, and a value-based rule could never match that fragment. A citizen's own address matches none of the entries and is masked exactly as before, including when both appear in one sentence.

    pii.allowlist_ordering — safety invariant. Detection runs first; the allowlist only exempts what was already found. An exempt contact is still detected, still counted, and still written to the audit entry — only the rewrite is skipped. An allowlist consulted before detection would suppress the match itself, making an exemption indistinguishable from a recognizer that quietly failed.

    The model receives the masked prompt. The system prompt tells it that tokens like <US_SSN:a1b2c3> are expected and not to ask the user to repeat them — so masking does not turn into a broken conversation.

    Non-streaming, on purpose. An output rail needs the complete response before anything reaches the user, and a grounding check cannot score a sentence that has not finished. Streaming and inline output rails are mutually exclusive; this stack picks the rails.

    The same families run again on the way out. scope.domain does not: it asks what the user wanted, and an answer cannot change that. prompt_attack does not either — it is scoped to inbound surfaces. content.action.llm_response is regenerate, which the rail reports as BLOCK and the engine reads as a retry instruction: regenerate is a stage-level action, never a rail verdict.

    A Claude judge splits the answer into claims and checks each against the chunks that were actually retrieved. Two numbers, deliberately separate — they fail differently. A confidently wrong answer is low-consistency, high-relevance; a correct but evasive answer is the reverse. Averaging them into one “quality” score hides both.

    With nothing retrieved the rail no-ops rather than inventing a baseline: grounding is architecturally scoped to retrieval-backed responses.

    A failed answer goes back to the model, never to the user. Only a second failure surfaces a person.

    ◀ still ungrounded after the last retry Escalated to the human review queue. The user gets REVIEW_TEMPLATE and a reference id — not a wrong answer.

    vault.unmask walks the reply for <ENTITY:token …tail> and decrypts each one back to the original value — only when pii.reversible is on, and only for a caller entitled to it. That is the whole point of vault tokens: the model never saw the raw SSN, and the user still gets their own data back.

    _converse() has several early returns — a blocked prompt, a model refusal, an exhausted regeneration budget. Deciding review here, in the wrapper, rather than at each of those sites, means a new exit path cannot forget to consult the trigger.

    Triggers: repeat failures (default) · any block · any mask · sampled 5% · none. The sample is derived from the request id rather than an RNG, so a trace replayed later lands in the queue the same way it did in production.

    Response server → browser

    A refused prompt must not become context for the next turn — otherwise the block is one turn of friction rather than a boundary. The trace itself always joins the 50-entry ring, blocked or not.

    Detections cross the wire redacted — kind, offsets, confidence, never the matched value. The raw value exists in exactly one place, the audit log, which in a real deployment sits under a different ACL from the response log.

    Violations render above the reply at the disclosure level the server chose — the client never decides how much to say. “View trace” opens the full stage tree for this request id.

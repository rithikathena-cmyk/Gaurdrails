Every answer is checked, twice

A public-services assistant with guardrails on the way in and on the way out. Personal details never reach the model, an agent cannot act without a person saying yes, and every request leaves a trace you can read afterwards.

How a request is checked, start to finish

Two phases, one pipeline. A document is classified once when it comes in — the judge (entities.py) only ever answers "what is this"; pii.kind_actions and pii.kind_mask_strategy, plain code with no model call, are the only thing that decides what happens to it. Every question afterward then walks five guardrail stages — a risk pre-check, the input rails, the agent with its own tool-call rails, an authorization check, and the output rails — the same path a request actually walks through routes/pipeline.py into Engine.converse().

Masking is not refusing. The name and phone number are detected and masked, and the request carries on — answered correctly from the Citizen Charter: own agricultural land in the society's area, then pay the admission fee and share capital.
